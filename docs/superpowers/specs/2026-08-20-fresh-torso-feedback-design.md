# Stage 1 第 0 帧升降反馈新鲜度修复设计

日期：2026-08-20

## 问题

Stage 1 Pick 在恢复 DataReplay 第 0 帧姿态时，升降柱实际已经从
`0.162 m` 到达约 `0.211 m`，但验收仍读取 `Vision.joints` 中动作前的
`body_joint` 缓存，误报约 `49.7 mm` 残差并阻止正式回放。

## 设计

`Vision` 为独立的升降柱订阅回调维护单调递增的反馈序号。回放器每次
刷新反馈时，不只执行一次 ROS callback，而是等待升降柱反馈序号前进，
从而保证随后读取的 `body_joint` 至少来自本轮刷新，而不是动作前缓存。

该修复只改变反馈读取的新鲜度：

- 不改变视觉 X/Y/Z 计算；
- 不改变修正后的升降柱目标或预置轨迹；
- 不改变新资产的 333 帧内容和时间戳；
- 不改变 D01 当前在 frame 20 启动的安排；
- 不绕过第 0 帧姿态验收。

## 验证

自动化测试必须先复现：普通关节消息持续到达，但旧实现只处理一条消息，
导致新的升降柱消息尚未被消费。修复后，同一测试应证明刷新函数会继续
处理 callback，直到升降反馈序号增加；超时后则返回，不得无限等待。

运行现有感知、任务和 DataReplay 相关测试，确认接口和回放合同不变。
部署后只读核对升降反馈；真机重试仍使用当前位置精确对位，不启用粗定位。
