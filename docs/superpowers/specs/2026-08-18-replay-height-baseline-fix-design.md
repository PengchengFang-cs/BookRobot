# DataReplay 抓取高度基准修复设计

日期：2026-08-18

## 问题

当前书本对位代码使用下面的高度公式：

```text
目标升降高度 = 当前 body_joint 高度 +（当前书本 Z - 录制书本 Z）
```

这个公式隐含假设当前升降柱已经位于 DataReplay 的录制起始高度。`S1_TABLE_PICK_BOOK` 的第 0 帧记录高度约为 `0.20 m`，但第一次真机对位从 `0.28 m` 开始。因此约 `+0.008 m` 的书本高度差被错误地计算成约 `0.288 m` 的升降目标，并超过本次真机实际可达的 `0.28 m` 上限。

## 目标

抓取对位必须以 DataReplay 的录制起始姿态为绝对基准。高度补偿后，实际升降柱位置与所需位置的误差不超过 `0.003 m`。本次修改不运行 DataReplay、不启动吸盘，也不改变现有视觉和底盘 X/Y 对位逻辑。

## 方案

固定使用以下量：

```text
replay_torso_m = 0.20
book_z_delta_m = observed_book_z_m - recorded_book_z_m
target_torso_m = replay_torso_m + book_z_delta_m
```

将 `target_torso_m` 限制在机器人已确认的 `[0.0, 0.28] m` 行程内。超出范围时直接报告错误，不再把目标裁剪到边界，因为裁剪会留下不可接受但容易被误认为成功的 Z 偏差。

`navnav_final` 的构建器仍负责生成 Y→Z→X 命令。FPC 适配层向构建器传入经过换算的虚拟 Z 位移，使构建器从当前实际高度生成上述绝对目标；不修改只读参考工程 `/home/unix_ai/navnav_final`。

## Z 对位判定

书本位于桌面上，升降柱移动不会改变书本在 `base_link` 中的原始 Z 坐标。因此不能用移动后再次检测得到的 `observed_book_z - recorded_book_z` 判断升降是否补偿完成。

实际有效残差定义为：

```text
effective_z_residual_m = book_z_delta_m - (actual_torso_m - replay_torso_m)
```

执行完升降命令后重新读取 `body_joint`，只有：

```text
abs(effective_z_residual_m) <= 0.003 m
```

才认为高度对位成功。否则对位入口报告明确错误并结束，不进入后续 DataReplay。

移动后的视觉检测仍用于重新关联书本和报告 X/Y 场景残差；Z 输出同时显示原始书本高度差和经过升降补偿后的有效残差，避免把固定桌面高度误报成控制失败。

## 接口与数据流

`BookAlignmentNavigator.align()` 接收已有的 `reference` 与 `observed` 三维点，完成：

1. 读取当前 `body_joint`。
2. 计算基于 `0.20 m` 的绝对升降目标。
3. 生成并执行现有 Y→Z→X 命令。
4. 再次读取实际 `body_joint`。
5. 计算并验证有效 Z 残差。
6. 返回命令数、目标高度、实际高度和有效 Z 残差。

任务编排层保存该结果，并在最终报告中区分原始三维检测残差与有效 Z 残差。

## 测试

自动化测试覆盖：

- 当前高度为 `0.28 m`、书本 Z 偏差为 `+0.008 m` 时，生成约 `0.208 m` 的目标，而不是 `0.288 m`。
- 正负书本 Z 偏差都以 `0.20 m` 为基准。
- 目标超出 `[0.0, 0.28] m` 时失败，不裁剪。
- 实际高度使有效残差不超过 `3 mm` 时成功。
- 实际高度使有效残差超过 `3 mm` 时失败。
- 发生失败时仍调用现有停止逻辑。
- 任务编排层报告补偿后的有效 Z 残差。
