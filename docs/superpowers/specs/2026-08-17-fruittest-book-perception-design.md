# FruitTest 书本感知替换设计

## 目标

第一阶段只替换 FruitTest 的视觉链。程序采集 Wanda 头部同步 RGB-D 帧，将彩色图发送给 RTX 5090 上既有的 DINO/SAM 场景分割服务，取得桌面书本的二维 bbox 和 mask，再在 Wanda 本机用深度、相机内参和当前头部/升降关节姿态计算 `base_link` 下的吸取点。

本阶段不改变 `navigation.py`、`arm.py` 的行为，不启动真机动作，也不处理完整比赛 Pipeline、DataReplay、OCR 或多本书任务编排。

## 方案选择

采用“FruitTest 轻量适配器”方案：保留 `Vision.find(...)` 作为任务层接口，在视觉模块内部增加 5090 mask 客户端和本地书本几何计算。

没有选择直接启动完整 ROS 2 perception gateway，因为当前目标只是验证 FruitTest demo 的前三步，完整 gateway 会引入尚未激活的运行配置。也不新建另一套 HTTP 推理服务，因为既有视觉合同已经固定为 gRPC `VisionService/Infer`，机器人侧入口为 `127.0.0.1:7443`。

## 组件

### 5090 mask 客户端

- 输入：一帧头部彩色图及其时间、尺寸和相机标识。
- 请求：固定的桌面书本场景 profile，不接受任意文本 prompt。
- 输出：每本书的置信度、bbox 和 bbox-local RLE mask。
- 网络端点和运行身份由配置提供，默认端点为机器人本机转发 `127.0.0.1:7443`。
- 客户端只负责二维视觉结果，不上传深度，不产生机器人坐标或动作。

### 本地书本几何

- 解码书本 mask，并仅使用 mask 内有效深度。
- 按相机内参把深度像素投影为相机三维点，再用 FruitTest 已有的相机到 `base_link` 标定转换点云。
- 在封面点云上估计书本长轴、短轴和顶面高度。
- 以机器人视角确定近端和右边缘，吸取点固定为：从近端沿长轴向内 `0.13 m`，从右边缘沿短轴向左 `0.10 m`，高度位于封面顶面。
- 输出至少包含吸取点、长短轴、尺寸、置信度和对应 mask，供日志与后续机械臂接入使用。

### FruitTest 接口

- `Vision.find(..., frame="base_link")` 返回选中书本的吸取点，保持任务层调用形式简单。
- `frame="map"` 时沿用现有 TF，将该吸取点从 `base_link` 转到 `map`。
- 第一版选择置信度最高的有效书本；多书排序和 `slot_index` 留到比赛 Pipeline 阶段。
- 保存一张检测调试图，画出 bbox、mask、长短轴和吸取点投影。

## 数据流

```text
头部彩色图 ──> 5090 DINO/SAM ──> bbox + mask
                                      │
头部对齐深度 + CameraInfo + 关节姿态 ─┴─> Wanda 本地三维点云
                                             │
                                             └─> base_link 吸取点
```

## 配置边界

新增的配置只覆盖视觉 RPC、书本 mask/depth 有效范围，以及固定的 `0.13 m`/`0.10 m` 吸取点偏移。现有导航接近距离和机械臂抓取高度等固定距离保持原值，等感知测试通过后再单独调整。

## 错误处理

没有新鲜同步帧、5090 无响应、没有书本 mask、mask 内深度不足或书本尺寸无法支撑固定偏移时，`Vision.find(...)` 返回 `None` 并记录明确原因，不调用导航或机械臂。

## 测试

- RLE mask 解码测试。
- 合成 RGB-D 平放书本测试，验证长短轴和 `0.13 m`/`0.10 m` 吸取点。
- 无效深度和过小书本返回无结果的测试。
- mock 5090 客户端测试，验证 `Vision.find` 的 `base_link`/`map` 输出。
- 保留现有 FruitTest 几何测试。

真机联调由用户完成；本次交付只运行不会发送机器人动作的离线测试。
