## 1. 一句话说明项目

当前项目让 Wanda 机器人使用头部 RGB-D 相机寻找桌上的书，通过 RTX 5090 上的
Grounding DINO + SAM 获得二维检测结果，在 Wanda 本机结合深度计算三维位置，
再利用已经录制好的 DataReplay 完成抓书和向小推车放书。

历史上已经打通并真机完成的是 **三本书 Stage 1 完整循环**。为缩短逐项优化实验，
当前 `--stage1-loop` 暂时固定执行两本书；它覆盖两次 Pick/Place、槽位 1/2 和一次
返回书桌。最终目标仍是五本书 Stage 1 在 8 分 30 秒内完成，再为拉车和结束保留
约 1 分 30 秒。

## 4. 当前 Stage 1 完整流程

当前 `--stage1-loop` 是速度优化用的两本书实验循环，而不是最终五本循环。

### 4.1 第一次到书桌

默认会执行第一次书桌粗导航：

1. 升降柱恢复到 `0.20 m`；头部回正并向下看，pitch 约 `0.25 rad`。
2. 头部依次向右看 `30/45/60/75°`，每个角度拍一张并检测书本。
3. 从检测结果选择距离最远的书，计算书桌方向上的直线路程。
4. 第一次起点不后退；右转、直行、左转，来到书桌前的精定位区域。

如果机器人已经人工放在书桌正面，可以显式跳过这一步：

```text
--skip-stage1-initial-coarse
```

### 4.2 抓书精定位

1. 5090 使用 `book.` 检测并分割书本。
2. Wanda 根据书本 mask 和深度拟合书本长短轴。
3. 抓取点固定为：从机器人视角近端沿长轴向内 `13 cm`，再从机器人视角右边缘
   沿短轴向左 `10 cm`。它本来就不是书本中心。
4. 每次选择机器人视角最右侧的可用书。
5. 将实时抓取点与 Pick DataReplay 第 0 帧参考点比较，得到 X/Y 误差。
6. 底盘最多修正三轮，每轮重新拍一张图；前后 X 允许 `±20 mm`，左右 Y 允许
   `±10 mm`。
7. 视觉 Z 只打印，不用于补偿。升降柱和整条动作必须保持 DataReplay 原始高度。

当前 Pick 参考点：

```text
base_link = (0.8981937, -0.2589220, 0.7568440) m
```

使用录像：

当前行为：

- 升降柱基准为 `0.20 m`，不叠加视觉 Z。
- 完整回放 333 帧，包含录像中的底盘速度。
- frame 20 发布后调用 `right_suction_start`。
- D01 等待在独立线程中，不阻塞后续 DataReplay 帧。

### 4.4 从书桌到小推车

1. Pick 完成后保持吸盘开启，先后退 `0.20 m`。
2. 底盘分六步左转，每步 `15°`，最终转到 `90°`。
3. 只在 `30/45/60°` 拍三张图；旋转完成后把三张图依次交给 5090，不并行。
4. 使用整车 `cart_body` 的三维中心估计书桌坐标系左右方向上的长距离路程。
5. 机器人在已经左转 `90°` 的方向直行到车旁。
6. 右转 `90°` 正对小推车，再前进 `0.20 m` 抵消最初的后退。

整车中心只用于这段粗导航，不用于 Place 最终前后距离。

### 4.5 推车精定位

1. 恢复 Place 2.4 录像姿态：升降柱约 `0.20 m`，头部 pitch 约 `0.25 rad`。
2. 5090 只检测 `cart_body`；不再额外检测无用的 `cart_platform` 和 `book`。
3. Wanda 在 `cart_body` bbox 内用灰度阈值和连通区域寻找黑色方块。当前源码阈值为
   `120`，并按几何关系从多候选中选择正确的 2/3/4 个标记。
4. 四点直接建平台；三点补出第四点；两点使用已知平台尺寸补出平台方向和深度。
5. 平台物理尺寸按宽 `0.75 m`、前后约 `0.29 m`；五个槽位中心距左边缘为
   `0.17/0.24/0.31/0.38/0.45 m`。
6. 当前槽位和录像参考决定左右；整车 bbox 宽度相对录像参考决定前后；平台方向
   决定 yaw。
7. 每张有效图立即使用。无有效平台才重拍，最多拍 5 张；底盘最多修正三轮。
8. 验收范围：前后 `±30 mm`、左右 `±20 mm`、yaw `±5°`。

## 6. 速度和耗时优化

当前分支已经完成以下优化：

- 粗导航直线速度上限设为 `0.5 m/s`。
- 精定位速度不变，旋转仍使用精度模式。
- 普通书本检测每轮只用一张新图和一次模型调用。
- 推车粗扫描只拍 `30/45/60°` 三张图，拍完后串行推理。
- 推车四角精定位只在图不可用时重拍，最多 5 张。
- Pick 和 Place HDF5 在第一本开始前加载到内存，当前两轮重复使用，不再每轮重新读取。
- Pick/Place 运行模块顺序初始化，避免并发修改 Python 全局模块状态。
- Wanda 将彩色图以 JPEG quality 85 发送，图像尺寸和 mask 坐标仍保持原始
  `1920×1080`；DINO 在 5090 内部再按模型预处理缩放。
- 视觉 RPC 客户端超时为 `10 s`。

## 14. 当前项目的工作思路和思考方式

本项目不是从头生成一条新的机械臂轨迹，而是以已经在真机录制并成功执行过的
DataReplay 为动作基准，再使用视觉把机器人移动到录像开始时的相对位置。接手人应
始终围绕这个主线理解问题：

```text
视觉找到当前目标
  → 计算当前目标相对机器人的位置
  → 与对应 DataReplay 第 0 帧的目标位置比较
  → 调整底盘和第 0 帧全身姿态
  → 完整执行原始 DataReplay
```

### 14.1 先复现录像起点，再执行录像

DataReplay 能成功的前提，不是机械臂在回放开始前已经碰到最终抓取点或放置点，
而是机器人、目标物和全身姿态之间的相对关系与录像第 0 帧一致。因此：

- 对位参考必须来自 DataReplay 第 0 帧，不能用吸盘接触帧代替；
- 回放前不仅要恢复底盘位置，还要恢复录像中存在的头部、升降柱、双臂、夹爪和
  灵巧手姿态；
- Pick 的视觉 Z 不再改变录像轨迹，因为录像本身已经包含书本高度和吸取动作；
- 视觉的作用是把现场变成“可以重新播放录像”的状态，而不是替代 DataReplay
  重新规划全部动作。

### 14.2 粗导航和精定位分开处理

粗导航只负责进入目标附近，不承担毫米级对位；精定位只在机器人已经正对目标后
工作：

- 粗导航优先使用明确的直角路径：转向、直行、再转回，减少狭小场地中的碰撞风险；
- 精定位使用实时 RGB-D 结果与录像参考计算误差，每移动一次就重新观察；
- 粗导航可以提高直线速度，精定位保持原来的低速和精度模式；
- 不要把整车中心等粗目标继续用于最终 Place，对最终动作有意义的是平台槽位和
  DataReplay 参考。

### 14.3 坐标和误差必须说清楚

讨论移动时统一以机器人当前正面为基准：

- `base_link +X`：机器人前方，也就是前后距离；
- `base_link +Y`：机器人左方，也就是左右误差；
- `base_link +Z`：向上，也就是高度；
- yaw：底盘在水平面内的朝向角。

每次调试都应同时打印“当前点、录像目标点、两者差值和最终执行的移动量”，避免只看
“还差几厘米”而不知道它属于哪个坐标方向。

### 14.4 先确认语义点，再讨论标定和控制

视觉误差应按下面顺序判断：

1. 原始图中目标是否真实可见；
2. DINO/SAM 是否找到了正确物体；
3. 选取的语义点是否符合任务定义，例如书本 13/10 点、推车黑标槽位或 Stage 3
   紫色交点；
4. 二维点转换成深度和 `base_link` 三维点是否正确；
5. 三维目标和 DataReplay 第 0 帧参考的差值是否正确；
6. 最后才判断底盘摩擦、控制误差或机械标定。

不要在语义点尚未确认时，通过移动机器人、修改偏移量或更换规则来掩盖视觉问题。

### 14.5 调试图必须来自算法真实输入

用于黑标连通域、深度和几何计算的图必须是相机原始图，不能使用已经画上 DINO/SAM
bbox、mask 或文字的 overlay 作为下一步算法输入。Overlay 只用于人查看。

一次实验应保存：

- 原始关键帧；
- DINO/SAM bbox 和 mask；
- 算法选中的书本点、车体点、黑标、平台边缘、槽位或 Stage 3 锚点；
- 对应数值、误差和实际移动；
- DataReplay 帧数与 D01 事件结果。

实验完成或失败后再把整个时间戳目录传回 5090。这样出现问题时可以区分是检测、
几何、导航还是回放，而不需要依赖现场记忆。

### 14.6 优先复用已经真机成立的简单关系

目前有效的技巧包括：

- 抓书使用固定的 13 cm / 10 cm 语义点，不改成书本中心；
- 连续抓多本书时，每一轮重新检测并选择当前最右侧的书；
- 从书桌到推车以及返回书桌使用直角路线，利用已知的后退/前进 `0.20 m` 相互抵消；
- 推车槽位使用平台宽度和固定槽位中心，不把一次录像中的单本位置当成所有书的位置；
- 四黑标允许得到 4、3 或 2 个有效点：四点直接算，三点补点，两点结合已知平台尺寸；
- 有效图立即使用；图不可用才重拍，不在同一张图上反复调用相同模型；
- HDF5 只加载一次到内存，后续循环复用，但每一轮仍重新恢复第 0 帧姿态。

### 14.7 修改和实验的协作方式

- 修改前先用一句话复述本次只要改变的行为，确认没有混入额外机制；
- 一次只处理当前明确的问题，不顺便重构、泛化或增加替代算法；
- 修改代码时默认不运行测试、模型或相机；需要验证时先向用户说明要验证什么；
- 真机实验得到授权并确认现场安全后，应完整记录和诊断，不要为每条只读日志重复询问；
- 实验失败先报告实际发生了什么和证据，再提出需要修改的具体位置；
- 机器人旧工程和DataCollector默认只读；当前选定仓库通过自己的部署脚本复制到`/home/unix_ai/fpc`。后续三位同学分别使用Git分支或独立克隆研发，完成的动作最终合并到`/home/cvailab/Ruan/Library_306`，不要三人共用一个工作树。

## 15. 新 TODO：参考直接绝对位置命令加快非精细动作

一次临时拍照脚本中的头部和升降柱动作表现得特别快、灵敏。已经确认主要原因是：

- 脚本直接向头部和升降柱控制话题发布绝对目标位置，绕过了遥操中的平滑处理；
- 每组姿态采用阶跃命令，例如升降柱直接从 `0.28 m` 变为 `0.00 m`，头部同时从
  `-0.057 rad` 变为 `+0.25 rad`；
- 脚本没有进行轨迹插值、速度渐变或单步幅度限制；
- 相同目标大约每 `0.05 s` 发布一次，即约 `20 Hz`，控制器会立即按自身允许速度
  追赶最终目标。

这不是修改了电机速度、控制器增益或永久配置。脚本停止后，机器人的速度设置不会
被永久改变；动作快是因为命令发送方式更直接。

- 推车或书桌扫描前的头部角度切换。
